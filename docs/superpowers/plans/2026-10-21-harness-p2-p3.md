# Harness P2/P3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the remaining P2/P3 harness items (hook changes, `log-analyst` Call samples, four skills, loop wiring, docs) and freeze the harness.

**Architecture:** Two hook changes in `.claude/hooks/` (plain Node.js, tested with `node:test` via root `npm test`); one agent edit; four new skills under `.claude/skills/`; small edits to two existing skills; docs. Skills are prose instructions, validated by one real run each in Task 10, which runs in the main session because it needs the user.

**Tech Stack:** Node.js ESM `.mjs` hooks with no dependencies, `node:test` + `node:assert/strict`, Claude Code skills/agents (Markdown + frontmatter), Mermaid 11.17.2 from jsDelivr.

**Spec:** `docs/superpowers/specs/2026-10-21-harness-p2-p3-design.md`

## Global Constraints

- Hooks: plain Node.js `.mjs`, no dependencies, shared code in `.claude/hooks/lib/`, tests in `.claude/hooks/*.test.mjs`, run with `npm test` at the repo root. Hook timeout is 10 s.
- Every new hook section is wrapped so a failure never hides the API key warning (existing `attempt()` pattern in `curriculum-status.mjs`).
- Skills: `.claude/skills/<name>/SKILL.md`, frontmatter `name`, `description`, `argument-hint`. No `disable-model-invocation` on the four new skills (it stays reserved for skills that spend money).
- Skill voice matches `run-exercise` / `log-analysis` / `build-exercise`: numbered `## N. …` steps, explicit stop conditions, a "done when" sentence. Load `superpowers:writing-skills` (or `writing-for-agents`) before writing a SKILL.md or agent file.
- HTML pages follow `CLAUDE.md` → "HTML write-ups, per exercise" exactly. Mermaid pinned once: `https://cdn.jsdelivr.net/npm/mermaid@11.17.2/dist/mermaid.min.js`. Nothing else external.
- The 1.3 page exemption is the constant `WRITEUP_EXEMPT = ["1.3"]`.
- `log-analysis` and `run-exercise` keep checking exactly eight `log-analyst` headings.
- Skills never overwrite user writing in RESULT.md or an existing HTML page without asking.
- Commits: `feat(harness): …` / `docs(harness): …`; validation outputs for 1.1 use `docs(1.1): …`. No Claude attribution, no `Co-Authored-By` trailer (user rule).

## Review Focus

1. A RESULT section that holds only an HTML comment or blank lines must count as empty. A section with only a `###` sub-heading or a table counts as content. Test in Task 1.
2. `docs/curriculum.md` with CRLF line endings must still yield domain weights. Test in Task 2.
3. A curriculum with no `(NN%)` domain headings, or a task whose domain has no weight, must not crash the SessionStart hook. It prints `Weighted progress: no domain weights found in docs/curriculum.md` or skips that domain. Test in Task 2.
4. `/data-flow` when the log RESULT cites is gone (logs are gitignored, so a fresh clone has none): say so and ask before falling back to the newest log, because the totals check would compare different runs. Covered by Task 5's step text.
5. `/drill` with an empty pool and no RESULT study points: say there is nothing to drill and point at `/study-notes`; never generate questions from nothing. Covered by Task 7's step text.

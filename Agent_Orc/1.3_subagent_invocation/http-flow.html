Subagent calls: the HTTP view

Task 1.3 · run log Log/20261020-001706_run.log · 2026-10-19 · model claude-sonnet-5-5

Caution. The run log does not record the raw HTTP bodies. The request bodies on this page are reconstructed from log fields. Each value in the evidence table (section 6) comes from the log.

1Overview

The API does not keep state. The model does not start a subagent. The model only writes a request for one. The client (Claude Code CLI) does the work and sends a new POST.

The run uses 14 POST requests to /v1/messages: 3 for the coordinator and 11 for the subagents.

2How the agent data goes to the model

  • The agent list is text in the description of the Agent tool, in tools[].
  • Each agent gives 3 items: name, description, tool names.
  • The subagent system prompt (AgentDefinition.prompt) stays on the client. The coordinator model does not see it.
  • The client sends the full system and tools[] again in each coordinator POST. The prompt cache makes this cheap. It does not make it absent.

Log evidence. POST #1 shows input_tokens: 2 and cache_creation_input_tokens: 33344. The fixed prefix (system, tools, agent list) is about 33k tokens.

3How the model tells which subagents to use

  • The model writes tool_use blocks. Each block names one agent in input.subagent_type.
  • No router on the server selects the agent. The model generates the name as tokens. It uses the agent list, the system prompt and the task.
  • Two tool_use blocks in one response mean "run in parallel".
  • stop_reason: "tool_use" tells the client to do the work and send a new request.

4How the client starts the subagents

  • For each tool_use block, the client starts a new and separate POST loop.
  • The client builds the subagent body from 2 sources: the AgentDefinition and the tool_use.input.
  • The subagent does not get the coordinator history. It gets only the input.prompt string.
  • The subagent loops until end_turn. Its last text is its result.

The first subagent POST has a 7,877-token prefix. The coordinator POST has 33,344. The system prompt and tools are different, so the prefix is different.

5How the coordinator gets the results

  • The client puts the final text of each subagent in a tool_result block.
  • Each tool_result.tool_use_id is the same as the tool_use.id of its request. This is how the model links a result to its call.
  • Both results go in one user message, in POST #2.
  • The client sends the full history again: task, the response #1 blocks, and the results.
  • The model can use a result only when the result is in messages[]. Thus synthesis comes in response #2, not before.

7Limits of this page

  • The log does not show the raw HTTP bodies. The CLI sends them and does not give them to the SDK stream.
